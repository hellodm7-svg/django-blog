----------------------------------------------------
1. 깃허브 저장소 생성
----------------------------------------------------

■ 깃허브(GitHub)란?
코드를 인터넷에 저장하고 관리하는 서비스.
마치 코드 전용 구글 드라이브라고 생각하면 됨.

■ 생성한 저장소 정보:
- 계정명: hellodm7-svg
- 저장소명: django-blog
- 주소: https://github.com/hellodm7-svg/django-blog
- 공개 여부: Public (누구나 코드 볼 수 있음)

■ 왜 깃허브에 올렸나?
- Render(배포 서버)가 깃허브에서 코드를 가져와서 실행함
- 코드 백업 역할
- 나중에 코드 수정 후 push하면 자동으로 블로그에 반영됨

----------------------------------------------------
2. 개인 액세스 토큰 (Personal Access Token)
----------------------------------------------------

■ 토큰이란?
깃허브에 코드를 올릴 때 사용하는 비밀번호 대용 인증키.

■ 생성한 토큰:
(보안상 여기에 저장하지 않음 - 필요시 깃허브에서 새로 발급)

■ 언제 쓰나?
터미널에서 git push 명령어로 코드를 올릴 때 필요.
잃어버리면 깃허브에서 새로 발급받으면 됨.

■ 주의사항:
토큰은 비밀번호처럼 취급. 타인에게 공유 금지.

----------------------------------------------------
3. 배포 준비 (코드 수정)
----------------------------------------------------

■ 배포용으로 추가/수정한 파일:

① requirements.txt
   - 프로젝트에 필요한 패키지 목록
   - Render가 이 파일 보고 필요한 것들 자동 설치
   - 주요 내용: Django, gunicorn, whitenoise, psycopg2

② build.sh
   - Render가 배포할 때 실행하는 명령어 모음
   - 패키지 설치 → 정적파일 수집 → DB 마이그레이션

③ config/settings.py 수정
   - SECRET_KEY: 환경변수에서 읽도록 변경 (보안)
   - DEBUG: 배포 환경에서 False로 설정
   - ALLOWED_HOSTS: Render 주소 허용
   - WhiteNoise: 정적파일(CSS, JS) 서빙용
   - dj_database_url: DB 설정 유연하게 변경

■ .gitignore 파일 생성
   - 깃허브에 올리면 안 되는 파일 목록
   - venv(가상환경), db.sqlite3(로컬DB), .env 등 제외

----------------------------------------------------
4. Render 배포
----------------------------------------------------

■ Render란?
코드를 받아서 24시간 서버로 실행해주는 무료 서비스.

■ 배포 설정값:
- 서비스명: django-blog
- 언어: Python 3
- 브랜치: main
- Build Command: ./build.sh
- Start Command: gunicorn config.wsgi:application
- Instance Type: Free ($0/month)

■ Environment Variables (환경변수):
- SECRET_KEY: my-super-secret-key-django-blog-2026
- DEBUG: False
- ALLOWED_HOSTS: *.onrender.com

■ 환경변수란?
코드에 직접 쓰면 안 되는 중요한 설정값을
서버 환경에 따로 저장하는 방식.
(비밀번호, API키 등을 코드에 직접 쓰면 깃허브에 노출됨)

■ 배포 결과:
블로그 주소: https://django-blog-16zr.onrender.com
상태: Live (정상 운영 중)

5. 전체 구조 이해
----------------------------------------------------

■ 각 서비스의 역할:

┌─────────────┬────────────────────────────┐
│ 서비스      │ 역할                       │
├─────────────┼────────────────────────────┤
│ 내 PC       │ 코드 작성 (Cursor IDE)     │
│ 깃허브      │ 코드 저장소 (설계도 보관)  │
│ Render      │ 서버 실행 (24시간 운영)    │
│ 블로그 URL  │ 실제 접속 주소             │
└─────────────┴────────────────────────────┘

■ 코드 수정 시 흐름:
Cursor에서 수정 → git push → 깃허브 업데이트
→ Render 자동 감지 → 재배포 → 블로그 반영 (3~5분)

■ 글쓰기 시 흐름:
블로그 주소 접속 → 로그인 → 글쓰기
→ Render DB에 저장 → 누구나 볼 수 있음
